# 历史回测：范围、数据和限制

`monitor/backtest.py` 复用正式异常波动引擎和指标筛选器，逐根回放同一合约、同一周期的完整 K 线；没有交易下单或 TG 发送功能。

## 数据来源

实现依据：[Binance 官方 public-data 仓库](https://github.com/binance/binance-public-data)。公开 USD-M K 线月包位于 `https://data.binance.vision/data/futures/um/monthly/klines/`。下载时验证对应 `.CHECKSUM` 的 SHA256，保留原始 ZIP、校验文件、下载时间和来源清单。不访问镜像，不改代理；如该数据服务拒绝访问则失败。公开历史归档不代表实时行情链路已经恢复。

已经准备的真实样本是 `data/backtest/BTCUSDT-5m-2026-06_07.json`：BTCUSDT，5 分钟，2026-06-01 00:00 至 2026-07-31 23:59:59.999 UTC，共 17,568 根，连续无缺口。原始归档校验：

| 月份 | 根数 | SHA256 |
|---|---:|---|
| 2026-06 | 8,640 | `782c555963c852ca768335de21d5743147e5d50bff449600f8fceb9ebe5273de` |
| 2026-07 | 8,928 | `ec750f7aa69c8f842fa1464a90ad4aa92452cfa767df9e8d70dc484e466c8fc3` |

CSV 导入要求币安官方 12 列 USD-M 格式，可含表头；JSON 是 Candle 字段数组。拒绝混合合约/周期、重复或倒序时间、未来或未收盘 K 线、非法价格/成交量。缺口会被报告，回测拒绝带缺口的数据，不用虚构 K 线填补。

## 实际模拟约定

- 全部四种形态、基准均值算法、裁剪比例、指标选择及筛选参数都使用传入配置。
- 预热使用正式引擎的最少历史要求。只用到信号当根已收盘 K 线；指标和引擎与实时服务使用同一有界历史窗口，绝不读取后续价格计算指标。
- 入场采用信号后下一根 K 线开盘价，加不利方向的单边滑点。下一根开盘已越过止损或目标则跳过。
- 默认最多持有 5 根 K 线；实际触及已确认结构止损/目标则提前退出。没有确认支撑阻力，不虚构目标价。
- 同一根 K 线同时碰到目标和止损时，先算止损；跳空越过止损按更差的开盘价执行。触及目标的有利跳空不计价格改善。
- 手续费默认单边 5 bps、滑点单边 3 bps，进出双边计入，均可配置。未模拟未来资金费率、杠杆、强平、订单簿排队和账户仓位。
- 同一合约周期不重叠持仓。回撤以假想的逐笔全资金 1 倍名义敞口再投资计算，明确不等于账户业绩。
- 独立记录 1、2、3、5 根后的方向净收益，并记录持仓段 MFE/MAE。后者只能使用完整 OHLC 区间，包含出场 K 线全幅，是描述性边界，不能证明盘中先后路径。

## 不把缺数据回测当成实盘验证

输出两组独立实验：

1. `strict_full_policy`：正式的当前配置。缺少所要求的历史流动性分位、价差或 OI 时不会放行。K 线月包没有这些字段，不能声称完成 100 分全策略验证。
2. `price_only_ablation`：明确移除 OI 必选、缺失流动性门槛和活跃度总分门槛，保留真实可得的成交额、K 线形态、指标、有效位移和成本后空间/盈亏比。这只是价格 K 线删减实验，不能代替第一组，也不会把缺失分数归一化成 100 分。

历史补充数据必须按信号的精确 `close_time` 索引，并带 `observed_at <= close_time` 的观测时刻；当前实时快照不得回填过去。每次报告列出缺数据排除数量。

## 阈值比较与参数建议

预先固定比较 1.5、2、2.5、3、4 倍。数据按时间 70% / 30% 划分训练段和留出段；边界前按最大持仓根数清除训练信号，训练交易不能跨越边界。训练段的前瞻诊断也不能借用留出段价格。

仅依据训练段的平均每笔成本后收益选择阈值；留出段结果单独报告，绝不用留出成绩选择“最佳”参数。训练和留出各需至少 30 笔已结束交易；不足时明确“样本不足”，不能称为实证最优。即使单次留出通过，也仍需其他币种、时期及真正未见数据复核，不保证未来获利。

看板只研究正式周期，初始筛选值为：5m 2.5、15m 2。它们是为了过滤小异常设置的**未验证初值**，并不是本次回测推导出的最优参数。

单币样本不能证明全市场有效，也不能验证新币上线消息、历史上市/退市全集、存活偏差、WebSocket 延迟或 TG 投递。新币历史不足行为由采集器测试验证，历史收益研究仍需当时的全合约清单及独立新币样本。

## 已执行的真实样本结果（2026-08-31）

上面的 BTCUSDT 5m、2026 年 6–7 月样本已经实际运行，耗时约 506 秒。配置为超级趋势 + SMC 全部确认、默认质量门槛、单边手续费 5 bps、单边滑点 3 bps、最多持有 5 根。当前 5m 初值为 2.5 倍。

- 2.5 倍产生 614 个原始候选。严格正式策略 0 笔，614 个候选都缺少必需的历史流动性数据，未擅自补造。
- 移除 OI 必选、缺失流动性和活跃度总分门槛的价格删减实验只有 1 笔，方向为阴阴趋势做空，触及止损；扣除双边手续费和滑点后约 **-0.2243%**。这是一次研究模拟，不是用户账户交易。
- 以下是删减实验的分段交易样本；严格策略各阈值均为 0 笔。

| 波动异常门槛 | 训练段已结束交易 | 留出段已结束交易 | 是否足够校准 |
|---|---:|---:|---|
| 1.5 倍 | 3 | 0 | 否 |
| 2 倍 | 1 | 0 | 否 |
| 2.5 倍 | 1 | 0 | 否 |
| 3 倍 | 1 | 0 | 否 |
| 4 倍 | 0 | 0 | 否 |

**结论是样本不足，不能据此推荐任何“回测最优倍数”，也没有证明这套组合能盈利。** 1.5 倍仅多得到两笔训练交易，留出段仍没有交易，不能用它当作降低门槛的证据。全策略验证仍需要完整历史流动性/OI、更多币种和独立留出时段。

看板可发现已登记数据集 `01176205c193b4cb95518a21`，以及真实报告任务 `65247d97444b430dbd3ef01bf78a9783`；原始报告保存在 `data/backtest/BTCUSDT-5m-2026-06_07.report.json`，看板任务封装保存在 `data/backtest/job-65247d97444b430dbd3ef01bf78a9783.report.json`，包含原始归档来源和参数快照。

首轮运行曾在训练出场边界上额外保守 5 根。所有阈值的边界排除交易数均为 0，因此随后移除这项重复保护不会改变这份报告的交易指标。后续代码共享相同指标上下文减少重复计算，等价性测试已通过；运行版本差异已写入报告，未冒充再次运行。

## 程序接口

```python
from monitor.history_data import download_binance_month, import_history
from monitor.backtest import run_backtest

download = download_binance_month('BTCUSDT', '5m', '2026-07', 'data/backtest')
candles = import_history('data/backtest/BTCUSDT-5m-2026-06_07.json', 'BTCUSDT', '5m')
report = run_backtest(candles, options={'threshold_profile': 'timeframe'})
```

该函数是同步 CPU 工作。Web 服务应放到后台线程任务，并限制单个任务及样本量。Web API 必须使用受限数据集 ID 或上传内容，不能接受用户提交的任意本机路径。

测试使用固定种子的**合成数据**验证因果顺序、成本、止损优先、缺数据拒绝、训练/留出分离和校验导入；测试通过不代表有盈利表现。

# PULSE v1.0.2 功能说明

本版增加真实行情采集入口、新合约提醒、指标共振、历史回测和可选 Telegram 纯文字推送；新增功能以本说明为准。**Telegram 默认关闭，没有下单功能，不需要交易 API Key。**“通过完整门槛”仅表示满足观察规则，不保证盈利，也不代表可以省略人工检查。

## 启动本机看板

需要 Python 3.12、Node.js 22.13 或更新版本。在项目根目录打开两个终端，分别保持运行。

终端一：

```powershell
python -m pip install -r backend/requirements.txt
python -m uvicorn monitor.api:app --app-dir backend --host 127.0.0.1 --port 8765
```

终端二：

```powershell
cd dashboard
npm ci
npm run dev
```

打开 [本机看板](http://127.0.0.1:5173)。依赖已安装时，可省略安装命令；停止时在两个终端分别按 Ctrl+C。电脑关机、休眠或后端进程停止都会中断采集，当前不是全天候托管服务。不要把未认证的本机接口直接暴露到公网。

若之前设置过 `PULSE_DISABLE_COLLECTOR=1`，请在后端终端将 `$env:PULSE_DISABLE_COLLECTOR = '0'` 后重新启动。真实采集、历史下载和回测使用本机看板。演示数据与真实数据隔离，连接失败不会用演示币价代替真实行情。

## 看板各位置

| 页面 | 用途 |
| --- | --- |
| 市场总览 | 按币种、周期、形态筛选；查看最新异常与强筛选结果 |
| 信号记录 | 查看已保存事件；展开 K 线、指标确认、支撑阻力和参考失效位/目标，关注或导出记录 |
| 行情下载与新币 | 查看逐币下载进度、实际 K 线内容、下载日志、待上架/开放交易提醒与实时覆盖 |
| 历史回测 | 下载或导入历史数据，选择数据集、持有根数，运行并导出回测报告 |
| 监测规则 | 设置波动门槛、形态、基准算法、指标组合和强信号要求；最后保存 |
| 系统状态 | 检查连接、数据更新时间、预热进度、缺口、处理积压，并重试官方连接 |

信号列表可切换“仅通过强筛选”和“全部原始异常”。后者用于核对被拒绝的原因，并不表示全部可交易；旧版未经过新规则判断的记录也不会自动升级为强信号。首次处理时距收盘已达 **90 秒**的候选只保留为历史异常，不进入新的合格信号，且会标记延迟。

保存规则后，后续接受的候选使用新规则；已经接受并排队的候选保留原策略。已保存信号带规则快照和标识，不会随着修改参数被悄悄重算。尚未落盘的内存队列不保证在进程崩溃后恢复。

## 全币种范围与新上架

范围按最新要求由币安元数据动态发现：**U_MARGINED 市场、quoteAsset=USDT、交易状态 TRADING**。包含加密资产、股票/ETF、港股、A股、韩股、大宗商品、指数等全部类别，以及永续和交割合约；未知资产类别仍保留并标注。不再纳入 USDC、USD1、U、BTC 等报价。正式下载、补缺和评分周期仅为 **5m、15m**，以 UTC 对齐，只分析连续且已收盘的 K 线。后台订阅的 1m 已收盘流只用于合成 5m/15m，不属于信号周期。旧范围和其他周期历史保留，但不再补齐、修复或评分；USDT 交割名称可能带日期后缀，使用官方报价字段判断，不用币名结尾筛选。范围明细见 [USDT 全类别范围说明](SCOPE_USDT.md)。

合约列表正常连接后约每 60 秒检查一次。首次成功获取的已有交易合约建立基线，不把全市场误报成新上架；后续结合上架时间和状态变化识别新合约，并持久去重。官方若提前返回待交易合约，会显示待上架，不能当作已开放交易；它之后转为 TRADING 时可产生独立的开放交易提醒。提醒始终保存在本机看板；Telegram 已连接并完成会话绑定、且“新上架提醒”开启时，只推送连接后新产生的事件，不补发基线、历史或重启前事件。

“发现/订阅了多少币”与“当前实际覆盖多少币”分别显示。只有对应币的实时心跳正常、周期历史就绪，才算实际覆盖。新币历史不足会单独标记；列入范围不代表已经能评分。首次预热、断线补齐和 OI 基准积累都需要时间。

早期检查遇到 HTTP 451；2026-08-31 晚间已从同一官方接口持续收到真实 K 线并下载历史。旧七周期口径当时观察到 561 个范围内合约、3,927 个合约周期、超过 131 万根已存 K 线；这些仅是历史观察值，不是当前两周期任务总数。当前任务总数按实时发现的 USDT 合约数×2计算。范围和库存会变化；这不代表全市场已完成预热或长时间稳定性已经验证。若再次收到访问拒绝，会显示真实原因；本程序不换代理、镜像或备用域名绕过限制。

## 看下载时各币的真实内容

直接进入[逐币行情下载](http://127.0.0.1:5173/?view=downloads)。上方“当前下载任务”展示正在请求哪些币、哪个周期、已存窗口根数与本轮接收批次；下方可搜索全部币种、筛选正在下载或失败，点击币名/周期查看详情。

- “刚下载的批次”展示最近已提交数据库的一批及其真实开高低收、成交额；下方列表按时间显示本地最新 20 根已收盘 K 线。没有数据时留空，不放演示样本。
- 未收盘的当前价格单独标注；断线或过期不冒充当前实时报价。历史价格会标“已存历史收盘”。
- 进度与详情约每 2 秒拉取一次，全库唯一库存约每 8 秒统计一次；写入条数包含重复覆盖，不能与唯一库存相加。恢复缓存、完成检查与新批次写入在日志中分开。
- “继续下载 / 重试失败”不会停止已有任务或清空数据。关机后重启会恢复缓存，只补当前监测窗口内的缺口；无需删除数据库或反复点重连。
- 本轮下载用于监测的历史窗口只有 5m=7天、15m=7天，并含计算所需额外根数；并非每币上市以来的所有数据。1m 只作内部实时合成源，不列入正式历史完成数。更早研究数据使用“历史回测”的归档下载。
- “导出已存 CSV”最多导出所选币/周期最近 60,000 根，带币名、周期及已收盘标记。此为看板自有 13 列格式，不是回测导入接受的币安原始 12 列格式。

已经下载的历史不等于当前在线、也不等于可立即评分；需要连续历史、实时心跳和所选指标/质量条件一起满足。新币没有足够历史时明确标识，不伪造补齐。

下载页现在用“已补齐历史窗口 / 总窗口”显示进度，另列合约总数、传统金融与交割数量；可筛选“全部传统金融”、具体资产类别及交割合约。信号列表和新上市事件也只显示 USDT。扩大范围不会把已存在的股票合约误报成刚上市。流动性分位按同报价币合约组核对完整新鲜数据，不把不同币种单位的成交额混排；当前组即 USDT。

**为什么第一次慢、以后怎么办：** 当前每个成熟合约只核验 5m 和 15m 两个历史窗口；例如运行时发现710个合约，对应1,420个正式合约周期。首次仍需分页下载、保存并核对连续性，实际根数因上市时间与缓存不同。5m、15m 是每根 K 线的时长，不是下载一批要等的时间。历史补齐与实时接收同时运行，已就绪的币种周期可以先监测，不需要等全市场全部完成。后续保存新增 1m 收线并按 UTC 合成 5m/15m，断线后只补这两个正式周期的缺口；对应周期未收盘时不生成正式信号。重启后的“本轮完成”会重新核对缓存，不能据此认为已存数据被清空。具体延迟与目前仍需验证的限制见 [采集性能记录](PERFORMANCE_NOTES.md)。

## 指标与强信号门槛

在“监测规则”中选择一个或多个指标，再选择“全部共振”或“任一确认”。默认选 **超级趋势 + SMC、全部共振**。阳阳/阴阴按趋势组合检查，阴阳/阳阴按反转组合检查；反转还要求近期翻转、交叉或已确认结构转变，不能仅凭两根颜色判断。

- 超级趋势：默认 HL2、ATR 10、倍数 3、Wilder 算法，可改为 TR 简单均值。
- SMC：默认内部结构周期 5、波段周期 50、反转确认有效 3 根；提供已确认的 BOS/CHoCH、支撑阻力、订单块和同周期 FVG 等辅助信息。
- EMA 双均线：可额外选择，默认快线 20、慢线 50。选择单个指标只改变共振要求，质量及已确认支撑阻力空间检查仍保留。

新增算法需要在本地指标注册代码和配置白名单中接入，并验证只使用当时已知数据；网页不直接执行粘贴的 Pine/Python 脚本。SMC 是基于所提供脚本的因果实现，不能视为 TradingView 原版全部绘图功能的精确复刻；改编部分沿用 © LuxAlgo 的 CC BY-NC-SA 4.0 非商业、署名及相同方式共享许可，详见 [指标说明与许可](INDICATORS_LICENSE.md)。

默认质量要求如下；它们是筛选条件，不是收益预测：

| 项目 | 默认值 |
| --- | --- |
| 活跃度 | 至少 80/100，缺失项不补分或放大总分 |
| 相对成交额 | 至少 1.8 倍 |
| 有效实体变化 | 至少 0.4%；趋势看两根净位移，反转看后一根实体 |
| 扣成本后位移及目标空间 | 至少 0.25%；已发生位移不代表未来利润 |
| 流动性分位 | 至少 0.4（0～1） |
| 买卖价差 | 不超过 8 bps（0.08%） |
| 成本后参考盈亏比 | 至少 2 |
| 成本假设 | 单边手续费 5 bps、滑点 3 bps；质量检查还计入价差 |
| OI / 缺失流动性 | 默认不强制 OI；默认不允许缺失流动性数据 |

参考失效位和目标必须有已确认结构依据，空间不足就拒绝，不虚构目标。实际手续费、价差和成交滑点可能不同；未计未来资金费率。

“最低波动异常倍数”指当前两根标准化真实波幅之和相对历史基准的倍数，不是价格涨跌速度。默认历史基准剔除两端各 2.5%，当前两根不参与自己的基准。“按周期过滤”采用下表与统一下限中的较高值；“统一倍数”只使用用户设置的下限。

| 周期 | 默认周期门槛 |
| --- | ---: |
| 5m | 2.5× |
| 15m | 2.0× |

**这组值是过滤小异常的未验证起点，不是已经回测得出的最佳参数。** 提高倍数通常减少信号数量，但不能保证提高胜率。

## 用历史检查规则

1. 先在“监测规则”保存想检验的配置。
2. 在“历史回测”选择合约、5m或15m及已结束月份，下载币安官方归档并校验 SHA256；也可导入币安原始 12 列 CSV 或 Candle JSON。导入前选对合约/周期，单次不超过 20 MB、60,000 根。网页按月下载。
3. 选择数据集及最长持有根数，开始回测。下载、导入和回测同一时间只运行一个研究任务；不要在任务运行时关闭后端。
4. 查看数据来源、缺口、缺数据排除数量、交易样本量和报告限制，再查看净收益、回撤、各形态表现及阈值比较；可导出 JSON 报告。

模拟只看信号当时已收盘的数据，下一根开盘加不利滑点入场，默认最多持有 5 根。入场已越过失效位或目标则跳过；同根同时触及目标和止损先算止损。手续费和滑点双边计入，缺口数据不补造且不能直接用于回测。

阈值预先比较 1.5、2、2.5、3、4 倍；按时间前 70% 训练、后 30% 留出验证，并清除跨边界影响。只根据训练段选择参数，训练和留出各需至少 30 笔已结束交易才有足够样本进行该项判断。样本不足、留出失败会明确显示；单次通过仍不能证明对其他币种或未来有效。

报告分“完整规则”和“价格 K 线删减实验”。普通月包没有历史全市场流动性分位、盘口价差和 OI 快照，完整规则可能因缺数据而没有交易；删减实验放松了这些要求及活跃度总分门槛，**不能冒充完整实盘策略验证**。没有模拟资金费率、杠杆、强平和真实订单成交；单币回测也不能验证历史上市/退市全集、新币提醒时效、WebSocket 延迟或 TG 投递。详细方法、数据说明及 MFE/MAE 的解释边界见 [历史回测说明](BACKTEST.md)。

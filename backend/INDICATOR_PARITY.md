# 指标源码与看板显示口径

## 为什么旧图与用户提供的源码不同

旧图使用 TradingView 的开源 `Lightweight Charts` 组件绘制 K 线，但它不是 TradingView 的 Pine 运行环境，也不会直接执行粘贴的 Pine 脚本。后端先用 Python 计算指标，网页再绘制后端返回的结果。此前网页只绘制超级趋势活动线和少量结构价位，没有绘制超级趋势翻转标记、背景高亮，以及 SMC 的 BOS/CHoCH、订单块、FVG、强弱高低点和价值区，因此视觉上明显少于 TradingView 原图。

不同交易所数据源、交易对、历史起点和收盘口径也会改变指标结果。本系统仅使用币安 U 本位合约的完整已收盘 K 线；TradingView 画面可能使用另一个数据源，并会显示尚未收盘的当前 K 线。

## 超级趋势一致性

默认参数与用户提供的 Pine v4 代码一致：

- 来源：`HL2 = (最高价 + 最低价) / 2`
- ATR 周期：10
- ATR 倍数：3.0
- 默认 ATR：Wilder RMA，对应 Pine `atr(Periods)`
- 可切换 ATR：真实波幅简单移动平均，对应 Pine `sma(tr, Periods)`
- 追踪带使用前一根收盘价和前一根追踪带
- 价格穿越前一根追踪带时翻转趋势

系统只在 K 线收盘后确认翻转，因此不会用未收盘价格提前产生买卖标记。API 同时返回趋势线和 `flips`，中文标记为“转为上涨”或“转为下跌”。背景高亮属于显示效果，不参与信号判断。

## SMC 一致性与安全差异

同周期、已收盘数据可以合法并因果复现的部分已经分别输出：内部与波段 BOS/CHoCH、已确认结构价位、活动订单块、等高点/等低点、同周期 FVG、已确认波段价值区、波段 HH/HL/LH/LL，以及当前强弱高低点。

以下原脚本行为不复现：

- `request.security(... lookahead_on)` 的高周期前视；
- 把后来才确认的标签回画到更早 K 线；
- 依赖尚未收盘 K 线的实时变化；
- TradingView 专属绘图对象和装饰样式。

图层的 `time` 或 `start_time` 是结果当时变得可知的 K 线，`confirmed_at` 是该 K 线收盘时间。`pivot_time` 和 `origin_time` 只说明结构来源，不允许网页在 `confirmed_at` 之前提前绘制。这会让本系统与 TradingView 原图不完全相同，但能避免未来数据泄漏和回测重绘。

## 中文图层与机器代码

网页显示全部采用中文；稳定英文缩写只保留在 `code` 字段供程序识别：

| 代码 | 中文 |
|---|---|
| BOS | 结构突破 |
| CHoCH | 趋势变化 |
| EQH / EQL | 等高点 / 等低点 |
| OB | 订单块 |
| FVG | 公允价值缺口 |
| Premium / Equilibrium / Discount | 溢价区 / 均衡区 / 折价区 |
| Strong / Weak High / Low | 强 / 弱高低点 |

图层开关只控制画面显示，不应更改当时保存的指标判断或回测规则。
